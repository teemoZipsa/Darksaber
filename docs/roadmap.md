# Darksaber : Extraction 프로젝트 로드맵

**기준일**: 2026-08-28

이 문서는 저장소 전체의 우선순위를 요약한다. 현재 플레이 규칙은 [GDD](GDD.md), 화별 스토리 상태는 [메인퀘스트 로드맵](main-quest-roadmap.md), 실험 계획은 [레이드 랩 계획](raid-lab/PLAN.md)을 각각 source of truth로 사용한다.

로드맵의 순서는 약속된 출시 일정이 아니라 **안정성 → 플레이 완성도 → 콘텐츠 확장** 순의 작업 판단 기준이다. 새 기능은 기존 서버 권위 저장과 생환 규칙을 우회하지 않아야 한다.

## 현재 기준선

| 영역 | 상태 | 현재 계약 |
|---|---|---|
| 핵심 출격 루프 | 완료 | 1~3인 파티, 30분 제한, 다른 마을 생환, DEAD/MIA/LEFT 손실과 보험·복구 |
| 전투·탐험 | 완료 | 필드 이동 + ATB/행동력, 지형·LoS, 공격·마법·도구·방어·휴식·조사 |
| 경제·마을 | 완료 | 배낭/창고/장비, 상점·시장·계약, 시설 업그레이드, 치료·휴식, 현상수배 |
| 메인 시나리오 | 1~31화 구현 | 필드·비공정·실내 목표와 보상은 유효한 생환 뒤 서버 저장에 확정 |
| 저장·온라인 | 운영 기준선 완료 | 계정/캐릭터, Postgres, 서버 권위 결과, 재접속, 월드 snapshot, 단일 shard |
| UI·접근성 | 주요 패널 완료 | Canvas 필드 + React DOM 차단형 UI, ko/en, 데스크톱·모바일 |
| 출격 기록 | V1 완료 | 캐릭터별 최신 20건을 로컬/서버 최종 저장과 마을·저널 UI에서 확인 |
| 몬스터 도감 | V1 완료 | 전체 61종의 조우·토벌을 서버 권위로 캐릭터별 저장하고 마을·저널에서 검색·필터·상세 확인 |
| 자동 검증 | 기준선 완료 | lint, client/server/test typecheck, unit/integration, coverage, desktop/mobile E2E |

## 지금: 안정성 게이트

기능 수보다 영구 저장의 정확성과 재현 가능한 회귀 검증을 우선한다.

### 1. 스토리 캠페인 레이드 랩

- 1~31화의 목표 달성 → 생환/실패 → 보상 저장을 연속 캠페인으로 실행한다.
- 퀘스트·아이템·동료·골드가 정확히 한 번만 지급되는지 확인한다.
- 보관 공간 부족, 출발 마을 복귀, 사망, 실종, 중도 복귀를 같은 캠페인에 포함한다.
- 발견된 기술 실패는 최소 seed와 회귀 테스트를 먼저 남긴다.

완료 기준: 동일 seed digest 재현, 중복 보상 0건, 실패 결과의 영구 보상 유출 0건, invariant 위반 0건.

### 2. 네트워크·저장 혼돈 테스트

- 전투·전리품·결과 메시지의 중복, 지연, 순서 역전을 주입한다.
- disconnect/reconnect와 ghost 만료, 서버 재시작 snapshot 복구를 반복한다.
- 허브 save revision 충돌과 최종 레이드 저장 spool 재처리를 함께 검증한다.
- 클라이언트 표시와 서버 최종 저장이 어긋나면 서버 저장을 기준으로 복구한다.

완료 기준: 레이드 결과와 출격 기록 정확히 1건, 아이템·골드 증식/유실 0건, 재접속 불가 고아 세션 0건.

## 다음: 플레이 완성도

### 3. 차단형 UI 마무리

- `RaidResultUI`를 React DOM 결과 패널로 이전한다.
- `FusionTempleUI`를 React DOM 합체/확인 흐름으로 이전한다.
- 포커스 순환, ESC/바깥 클릭, 320~390px와 UI 120%, 모션 감소를 기존 패널 계약과 맞춘다.
- 월드 좌표 HUD와 방사형 행동 메뉴는 Canvas에 유지한다.

완료 기준: 남은 독립 Canvas 차단형 패널 0개, desktop/mobile Playwright 회귀 통과.

### 4. 오디오·피드백 완성

- 선택 자산으로 남은 지형 발소리 3개와 BGM 7개를 라이선스 확인된 자산으로 채운다.
- 전투·출격·생환·실패 전환의 음량, 중복 재생, 포커스 상실 복귀를 실제 브라우저에서 검수한다.
- 필수 자산 정책과 선택 자산 정책을 유지해 누락이 시작 실패로 이어지지 않게 한다.

완료 기준: `verify:assets` 선택 누락 0건, 음소거/볼륨/탭 전환 회귀 통과.

### 5. 1~31화 실제 플레이 검수와 밸런스

- 각 화의 입장, 목표 HUD, 이벤트 포커스, 보스/경비 판정, 복귀, 전리품 로그를 순차 점검한다.
- 출격 기록과 운영 지표로 생환율, 평균 시간, 실패 원인, 직업·행동 편중을 비교한다.
- 단일 seed나 한 번의 플레이만으로 전투 수치를 조정하지 않는다.

완료 기준: 화별 체크리스트 완료, 진행 차단 0건, 회귀 seed 보존, 조정 전후 동일 cohort 보고서 비교.

## 이후: 확장 판단

### 6. 메인 시나리오 32화

- 원본 MAP/set/이벤트/보상 자료의 재현 가능성을 먼저 검증한다.
- 1~31화와 같은 데이터 원장, 서버/로컬 공유, 생환 후 보상 확정 계약을 만족할 때만 런타임에 추가한다.
- 33화 이후는 필요한 원본 세트가 확보되기 전까지 구현 대상으로 잡지 않는다.

### 7. 운영 확장

- Postgres 백업·복원 훈련, 장시간 WebSocket 부하, 저장 spool 복구와 지표 경보를 운영 절차로 고정한다.
- 다중 shard는 raid instance 배치, lease 소유권, cross-instance 라우팅 설계가 끝난 뒤 별도 단계로 진행한다.
- 공개 상용 배포 전 원작 명칭·그래픽·음원·원문 자료의 권리를 검토하고 필요한 고유 자산 교체를 완료한다.

## 현재 비범위

- PvP, 길드, 채팅, 경매장
- 완전한 다계정 공유 파티 진행도
- 자동 다중 shard 배치와 무제한 수평 확장
- 원본 자료 계약이 확인되지 않은 33화 이후 시나리오

## 공통 완료 조건

코드 작업은 최소한 아래 검증을 통과해야 한다.

```bash
npm run lint
npm run typecheck
npm test
npm run test:e2e
```

릴리스 후보는 coverage, client/server build, 필수 자산 검증과 배포 문서의 운영 점검을 추가한다. 스토리 원본 대조가 필요한 작업은 `DARKSABER_ORIGINAL_SOURCE_ROOT`가 설정된 환경에서 `npm run verify:story`를 실행한다.
